Poke API

API REST de pokémon construida con NestJS, Mongoose y MongoDB. Esto es un servicio HTTP: no hay interfaz de usuario, se consume desde tu cliente, tu terminal o tu aplicación.

Base URL https://poke-api-softdo.up.railway.app/api/v1

Todas las rutas están prefijadas con /api/v1. Las respuestas son JSON.

# Stack

  • NestJS
  • TypeScript
  • MongoDB
  • Mongoose
  • Railway

# Endpoints

Seis endpoints. Todos cuelgan de la base URL de arriba.

  • GET /api/v1/pokemon

    Lista los pokémon almacenados, ordenados de forma ascendente por número de pokédex.

    Query params (opcionales)
    ParamTipoDefaultDescripción
    limit number > 0 5 Cantidad de registros a devolver.
    offset number > 0 0 Registros a saltar (paginación).
    curl 
    # todos los pokémon con los valores por defecto
curl https://poke-api-softdo.up.railway.app/api/v1/pokemon

# página de 20 registros, saltando los 40 primeros
curl "https://poke-api-softdo.up.railway.app/api/v1/pokemon?limit=20&offset=40"
    200 OK 
    [
  { "_id": "6a8d1725c3e411bb29f3180c", "name": "bulbasaur", "numPokemon": 1 },
  { "_id": "6a8d1725c3e411bb29f3180d", "name": "ivysaur",   "numPokemon": 2 }
]
  • GET /api/v1/pokemon/:term

    Busca un pokémon por id de Mongo, por número de pokédex (numPokemon) o por nombre. El nombre no distingue mayúsculas. Devuelve 404 si no existe.

    curl 
    # por número de pokédex
curl https://poke-api-softdo.up.railway.app/api/v1/pokemon/4

# por nombre
curl https://poke-api-softdo.up.railway.app/api/v1/pokemon/charmander

# por id de Mongo
curl https://poke-api-softdo.up.railway.app/api/v1/pokemon/6a8d1725c3e411bb29f3180f
    200 OK 
    {
  "_id": "6a8d1725c3e411bb29f3180f",
  "name": "charmander",
  "numPokemon": 4
}
  • POST /api/v1/pokemon

    Crea un pokémon. name y numPokemon son obligatorios y únicos; el nombre se guarda en minúsculas. Cualquier propiedad extra en el body es rechazada.

    Body — application/json
    CampoTipoRequeridoReglas
    name string Sí Mínimo 1 carácter. Único.
    numPokemon number Sí Entero positivo, mínimo 1. Único.
    curl 
    curl -X POST https://poke-api-softdo.up.railway.app/api/v1/pokemon \
  -H "Content-Type: application/json" \
  -d '{ "name": "mewtwo", "numPokemon": 150 }'
  • PATCH /api/v1/pokemon/:term

    Actualiza un pokémon existente. El :term admite lo mismo que la búsqueda: id de Mongo, número de pokédex o nombre. El body es parcial: envía solo los campos que quieras cambiar.

    curl 
    curl -X PATCH https://poke-api-softdo.up.railway.app/api/v1/pokemon/charmander \
  -H "Content-Type: application/json" \
  -d '{ "name": "charmander-shiny" }'
  • DELETE /api/v1/pokemon/:id

    Elimina un pokémon. A diferencia de GET y PATCH, aquí solo se acepta el id de Mongo: cualquier otro valor devuelve 400 Bad Request. Responde { "status": "OK" }.

    curl 
    curl -X DELETE https://poke-api-softdo.up.railway.app/api/v1/pokemon/6a8d1725c3e411bb29f3180f
  • GET /api/v1/seed

    Puebla la base de datos con los primeros 100 pokémon consumidos desde la PokeAPI pública. Responde con el texto SEED EXECUTED.

    Operación destructiva: borra todos los registros existentes antes de insertar los nuevos.

    curl 
    curl https://poke-api-softdo.up.railway.app/api/v1/seed

# Cómo empezar

  1. Puebla la base de datos

    Si la base está vacía, llama una vez al seed para cargar los primeros 100 pokémon.

    curl 
    curl https://poke-api-softdo.up.railway.app/api/v1/seed

  2. Consulta el listado

    Pide los pokémon paginados con limit y offset.

    curl 
    curl "https://poke-api-softdo.up.railway.app/api/v1/pokemon?limit=10"

  3. Trabaja con un pokémon

    Búscalo por id, número o nombre y, desde ahí, créalo, actualízalo o elimínalo.

    curl 
    curl https://poke-api-softdo.up.railway.app/api/v1/pokemon/pikachu

      Visión general

      La API expone un único recurso, pokemon, y un endpoint auxiliar de seed pensado para desarrollo. No requiere cabeceras de autenticación: todos los endpoints son públicos.

      Las peticiones con cuerpo deben enviar Content-Type: application/json. Las respuestas son JSON, con la única excepción de GET /api/v1/seed, que devuelve texto plano.

      Sin autenticación. No hay guards, API keys ni cabeceras de sesión en el proyecto. Cualquier cliente puede llamar a cualquier endpoint, incluido el de seed.

      Base URL

      Todas las rutas cuelgan del prefijo global api/v1, configurado con app.setGlobalPrefix('api/v1').

      Producción https://poke-api-softdo.up.railway.app/api/v1
      Local http://localhost:3005/api/v1
      Esta página —
      Puerto en local. La app arranca con process.env.PORT ?? 3000, pero el esquema de validación de entorno (Joi) rellena PORT con 3005 cuando no está definida en el .env. Si no fijas PORT, la API escuchará en el 3005.
      El playground usa rutas relativas. Las peticiones se lanzan contra /api/v1/… sobre el origen actual, así que funciona igual en local y en Railway sin depender de CORS (la web se sirve desde la propia API mediante ServeStaticModule).

      Modelo Pokemon

      Cada documento de la colección tiene dos campos propios más los que añade MongoDB. Ambos campos son únicos e indexados.

      CampoTipoNotas
      _id string ObjectId generado por MongoDB.
      name string uniqueindex Se normaliza a minúsculas al crear y al actualizar.
      numPokemon number uniqueindex Número de la pokédex. Es el criterio de orden en el listado.
      __v number Versión interna de Mongoose. Se excluye únicamente en el listado paginado.

      Validación global

      Un ValidationPipe global procesa todos los cuerpos y query params con esta configuración:

      • whitelist: true — elimina las propiedades que no estén declaradas en el DTO.
      • forbidNonWhitelisted: true — y además responde 400 si llegan propiedades desconocidas, tanto en el body como en la query string.
      • transform: true con enableImplicitConversion: true — convierte los tipos automáticamente, por eso ?limit=5 llega al DTO como número.
      Cuidado con los campos extra. Enviar { "name": "pikachu", "tipo": "eléctrico" } devuelve 400 con property tipo should not exist. Lo mismo con un query param no declarado, p. ej. ?page=2.

      Códigos de error

      CódigoCuándo ocurreMensaje de ejemplo
      400 El body o la query no pasan la validación del DTO, o incluyen campos no declarados. numPokemon must be a positive number
      400 Se intenta crear o actualizar un pokémon con un name o numPokemon que ya existe (índice único, error 11000 de Mongo). Pokemon exist in db {"name":"pikachu"}
      400 En DELETE, el id no es un MongoID válido (lo rechaza un pipe personalizado antes de tocar la base de datos). abc is not a valid MongoID.
      400 En DELETE, el MongoID es válido pero no existe ningún documento con ese _id. Pokemon with id: '...' not found.
      404 En GET /:term y PATCH /:term, no hay coincidencia por número, MongoID ni nombre. Pokemon with id, name or numPokemon "x",not found
      500 Cualquier otro fallo al crear o actualizar. Cant operation pokemon - Check server logs.

      Todos los errores siguen el formato estándar de excepciones de NestJS: { "message": …, "error": …, "statusCode": … }.
